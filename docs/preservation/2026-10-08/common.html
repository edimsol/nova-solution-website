“구현”은 해당 HTML·CSS·JavaScript에 동작 코드가 있다는 뜻입니다. 브라우저에서 재현을 완료했다는 의미는 아닙니다. 실제 로컬 브라우저 점검 결과는 별도 브라우저 확인 기록을 기준으로 읽습니다. 지도 정보 정확성·외부 Kakao 이동과 문의 수신 성공은 별도 확인이 필요합니다. 지도 UI·줌 조작 등 실제로 확인한 범위는 확인 기록에 구분되어 있습니다.

현재와 미래의 경계. 이 문서는 변경 전 사이트를 설명합니다. 새 SVG 자산과 향후 novascroll·Pretendard 요구는 리뉴얼 명세에 분리했습니다. novascroll과 Pretendard가 현재 운영 사이트에 설치·적용되었다는 뜻이 아닙니다.

메뉴의 조작과 상태

데스크톱에서는 hover 또는 focus-within으로 하위 메뉴를 보여주며, 상위 메뉴 클릭은 기본 이동을 취소하고 해당 메뉴를 열거나 닫습니다. Overview 링크를 사용하면 상위 페이지로 이동합니다. 한 메뉴를 클릭해 열 때 JS로 열린 다른 메뉴를 닫습니다. ↓는 하위 메뉴를 열고 첫 링크로 포커스를 이동합니다.

햄버거 버튼의 접근성 라벨은 “메뉴 열기”와 “메뉴 닫기”로 바뀝니다. 열 때 첫 메뉴에 포커스를 주고 body의 nav-open 클래스로 배경 스크롤을 잠급니다. 링크 선택·헤더 바깥 클릭으로 닫습니다. Escape로 닫으면 햄버거 또는 열린 메뉴 트리거로 포커스를 복원합니다. 모바일 nav는 max-height calc(100svh - 72px) 내에서 독립 세로 스크롤됩니다.

04. 페이지별 상호작용의 상태와 입력

Home — 전체화면 전환과 내부 스크롤

  • 첫 진입에 1750ms 로고 연출. 진행률 .76 이후 reveal 단계, 완료 시 entry 숨김 및 헤더·hero-copy 등장. reduced-motion이면 즉시 완료.
  • 슬라이드 순서와 hash: home → company → solutions → technology → resources(표시명 Industries) → contact. 처음에는 일치하는 hash, 없거나 일치하지 않으면 첫 슬라이드.
  • JS가 오른쪽 도트, “01 / 06” 형식 카운터, “SWIPE · SCROLL · ARROW KEYS” 안내를 생성. 도트는 개별 버튼과 aria-label 사용.
  • body의 스크롤을 막고 각 절대 위치 section에서 overflow-y:auto. 휠의 절댓값이 12 미만이면 전환하지 않음. 활성 섹션이 해당 방향으로 더 스크롤되면 내부 스크롤 우선; 끝에서 다음/이전 슬라이드로 전환.
  • pointerdown/up의 세로 차이가 58px보다 크고 가로 차이보다 크면 슬라이드 변경. 이동 후 클릭은 한 번 취소. 휠과 달리 이 포인터 전환 경로에는 내부 끝 여부 검사가 없음.
  • ↓/PageDown 다음, ↑/PageUp 이전, Home 처음, End 마지막. 전역 keydown이며 입력 대상 필터가 없음.
  • 760ms Web Animations 전환, 중복 전환 차단. 다음 방향은 새 섹션 scrollTop=0, 이전 방향은 새 섹션 맨 아래. 완료 뒤 클래스/aria-hidden/카운터 갱신, history.replaceState로 hash 변경. reduced-motion이면 화면 전환 애니메이션 생략.
  • HVAC/EDIM 카드 포인터 기울기는 hover 가능·fine pointer에서 실행. 홈 하단 문의는 mailto:ys.lee@edimsol.com?subject=NOVA%20Solution%20Inquiry.

Company — 카드, 모달, 위치 지도

  • 카드 5개는 about, mission, history, foundation, location을 엽니다. JS 초기화 시 각 section에 role=dialog, aria-modal=true, aria-hidden=true 및 닫기 버튼을 추가.
  • 열면 배경 버튼과 모달 표시, body 잠금, URL hash 변경. 카드의 위치·크기를 출발점으로 560ms 확대, 닫기는 380ms 역방향 연출. reduced-motion이면 이 연출 생략.
  • 닫기 버튼·배경 클릭·Escape로 닫고 hash를 제거, 원래 카드에 포커스 복원. 초기 URL hash와 같은 패널도 자동 열림. 같은 페이지의 company.html#... 링크를 가로채 패널을 엽니다.
  • 각 모달은 자체 세로 스크롤. 닫기 버튼은 sticky. 열기 애니메이션 이후 닫기 버튼으로 포커스 이동.
  • 위치 지도: Leaflet, office [37.2140373, 127.1019493], 초기 zoom 10, 타일 maxZoom 19, scrollWheelZoom=false, 오른쪽 상단 줌 버튼, “NOVA Solution · 8F 807” tooltip.
  • 지도 영역 노출 임계 .38 뒤 180ms 대기, zoom 17까지 2.5초 flyTo. 위치 모달을 열 때 80ms 뒤 invalidateSize 후 2.2초 flyTo가 별도로 호출됩니다.
  • 포인터 거리에 따라 배경 점의 크기·투명도 및 핀의 확대·그림자가 반응하며 포인터 이탈 시 복귀. 주소 원문과 Kakao Maps 검색 링크는 Company 내용 문서에 보존.

Solutions — 자동 순환 카드

  • HVAC/EDIM 각각 초기 activeIndex=0. 원본 카드들을 복제해 뒤에 붙이며 clone은 aria-hidden=true, tabIndex=-1.
  • requestAnimationFrame으로 0.018px/ms 이동, 한 프레임 elapsed 최대 40ms. 원본 카드 묶음 폭을 넘으면 scrollLeft를 되감아 순환합니다. reduced-motion이면 자동 이동하지 않음.
  • 이전/다음 버튼, track의 ←/→는 2600ms 일시 정지 후 카드 위치로 이동. 이동 방식은 기본 smooth, reduced-motion에서는 auto.
  • pointer capture로 가로 드래그. 6px 넘으면 dragged로 판단해 카드 링크 클릭을 취소. pointerup/cancel 뒤 가까운 카드에 맞춥니다.
  • mouseenter는 900ms, focusin은 2600ms 일시 정지. 포인터가 머물러 있는 전체 시간 동안 정지하는 구조는 아닙니다. 가까운 카드에 is-active 부여.
  • 페이지 y축은 mandatory scroll snap, 카드 x축은 스냅. 자동 이동·드래그 중 카드 snap을 해제. 기존 가로 scrollbar는 숨김.

09. 빌드·배포와 운영 경계

저장소에서 확인되는 구조

프레임워크·package.json 없이 11개 루트 HTML, 공통 styles.css/script.js, assets, partials를 사용하는 정적 사이트입니다. 원본 README의 로컬 예시는 node build-site.mjs, python3 -m http.server 4173입니다. 현재 작업 환경의 로컬 확인 주소는 http://localhost:8000/이며 포트 변경은 배포 구조 변경이 아닙니다.

  1. 공통 조각 생성: build-site.mjs가 partials/header.html 및 footer.html을 루트 HTML의 첫 header/footer 위치에 치환하고 일부 페이지에 aria-current를 부여합니다. 이 스크립트는 소스를 수정합니다. Windows의 join(root.pathname, file) 경로 처리에 문제가 있어 향후 사용 시 fileURLToPath 기반 수정이 필요합니다.
  2. 배포 빌드: scripts/build-pages.mjs는 7자리 hexadecimal commit SHA를 요구하고 루트 HTML 개수가 정확히 11개인지 검사합니다. dist를 새로 만든 뒤 CSS/JS 참조의 query를 SHA로 바꾸며 외부 URL이 바뀌지 않았는지 검증합니다.
  3. 자산 수집: 루트 HTML의 ./assets/ href/src와 styles.css/script.js 안의 이미지·bin·glb 참조를 수집. 공개 자산 assets/recruitment-2026-web-developer.png도 명시 복사. 경로가 assets 밖으로 나가면 실패합니다.
  4. 배포 제외: README.md, build-site.mjs, partials, .github를 dist에 포함하지 않도록 검사. .gitignore의 dist는 생성 결과이며 Git에서 제외됩니다.
  5. GitHub Actions: main push 또는 workflow_dispatch → checkout → configure-pages → short SHA → node scripts/build-pages.mjs → dist upload → deploy-pages. Pages 배포 concurrency는 pages, cancel-in-progress=false. shared header/footer 생성은 이 workflow에서 자동 실행하지 않습니다.

Cloudflare 운영 응답의 추가 요소 — 저장소 소스와 분리

동일 보존 작업의 운영 HTTP 조회에서는 대상 11개 HTML 응답이 모두 200이었으며, 11개 운영 응답에서 Cloudflare beacon 스크립트가 추가된 것을 확인했습니다. index/contact 응답에서는 mailto 링크가 /cdn-cgi/l/email-protection#...로 변환되고 /cdn-cgi/scripts/5c5dd728/cloudflare-static/email-decode.min.js가 추가되었습니다. contact의 이메일 텍스트도 __cf_email__ span으로 치환됩니다. 이는 저장소의 원문 이메일/링크와 구별해야 하는 운영 응답 변환입니다.

근거 원문은 운영 Home HTML, 운영 Contact HTML, 대조 결과는 운영·로컬 대조 기록에 별도로 보존합니다. Cloudflare 스크립트·이메일 난독화·CSS/JS 버전 query·공백/HTML entity를 문서화한 방식으로 정규화한 뒤 11개 페이지가 모두 baseline과 일치했습니다. 이는 원문 바이트 전체가 같다는 뜻이 아닙니다. HTTP 응답 성공은 지도·폼 수신·전체 브라우저 동작의 검증을 뜻하지 않습니다.

검토한 저장소에는 Cloudflare Workers/Pages 설정, wrangler 설정, DNS·프록시·캐시 규칙 또는 계정 연결 정보가 없습니다. 운영 HTML에 Cloudflare 스크립트가 있다는 증거만으로 DNS/TLS/캐시 설정이나 Cloudflare 계정 권한을 확정하지 않습니다. GitHub Pages workflow와 운영 응답 변환은 구분해 기록합니다.

Cloudflare를 추가하거나 현황을 인계할 때에는 도메인 소유 계정·zone, DNS 레코드와 프록시 여부, 실제 원본 호스팅, TLS 모드, 캐시 무효화 방식, 배포 후 확인 담당자를 별도 운영 기록에 남깁니다. 도메인 novasol.co.kr과 GitHub Pages 원본 연결이 어디서 관리되는지 확인한 뒤 기록해야 하며, 이 문서 작성이 DNS·인증서·배포 대상을 변경한 것은 아닙니다.
